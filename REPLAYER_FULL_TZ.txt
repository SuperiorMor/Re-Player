1. ОБЩИЕ СВЕДЕНИЯ, ПЛАТФОРМА И ЖЁСТКИЕ АРХИТЕКТУРНЫЕ ОГРАНИЧЕНИЯ
================================================================================
1.1. О продукте:
- Название: Re:Player (брендирование: RE:Player).
- Платформа: Android TV (Compose Android TV / Material3 TV, minSdk 24, targetSdk 35).
- Целевые устройства: телевизоры Android TV и Яндекс ТВ диагональю 43" и 50" (и аналогичные ТВ-приставки), где Google-сервисы могут отсутствовать или быть ограничены.
- Ориентиры по UX и функциональности:
  * nPlayer — удобная работа с сетевым контентом (UPnP/DLNA), переключение аудиодорожек и субтитров.
  * Televizo — работа с IPTV (M3U/M3U8), XMLTV телепрограммой (EPG) и архивами передач.
  * Google TV — современный чистый вид телепрограммы и карточек на Главном экране.

1.2. Жёсткий стек воспроизведения:
- Движок плеера: СТРОГО LibVLC (`org.videolan.android:libvlc-all:3.5.1`).
- Запрещено возвращать ExoPlayer / Media3 и кастомные экстракторы (в ранних версиях Media3 вызывал рассинхрон звука и зависания на MPEG4/AVI/DivX/Xvid).
- Поддерживаемые форматы: видео (MKV, AVI, MP4, TS и любые поддерживаемые LibVLC), аудио, изображения (если открываются из DLNA).
- Во время воспроизведения экран ТВ не должен гаснуть (`FLAG_KEEP_SCREEN_ON`).

1.3. История и ограничения Google Drive:
- Изначально (v0.1.x–v0.6.x) рассматривалась интеграция Google Drive, однако из-за отсутствия Google-сервисов на части ТВ (Яндекс ТВ) и ограничений scope `drive.file` у TV OAuth Client ID в v0.7.0+ было принято окончательное решение сосредоточиться на UPnP/DLNA и IPTV.
- При аудите проверить репозиторий на отсутствие мёртвого кода/зависимостей Google Drive (в частности, проверить `tools/auth_gdrive.py`, манифест и конфиги).

1.4. Сборка и релизы:
- Сборка подписывается keystore (`app/keystore/replayer.keystore`, единая подпись во всех релизах для бесшовного обновления поверх установленной версии).
- Автоматическая сборка через GitHub Actions (`.github/workflows/build.yml`) и единый скрипт релиза `tools/publish_release.py`.
- Имя релизного APK: `RePlayer-v{versionName}.apk`.
- В релизах GitHub формируется понятный русскоязычный список изменений «Что нового?».

3. ДИЗАЙН-СИСТЕМА, АЙДЕНТИКА, ТИПОГРАФИКА, ЦВЕТА И ИКОНКИ

3.1. Общая айдентика и цвета (в стиле логотипа RE:Player):
- Тёмная глубокая ТВ-палитра (темно-сине-графитовый фон, карточки с полупрозрачным тёмным фоном и тонкими бордерами).
- Фирменные акценты:
  * Электрик-циан / голубой: оттенки `#14D4F4` / `#38D4F8` (как «RE:» на логотипе).
  * Янтарно-оранжевый / тёплый золотой: оттенки `#FF8A1E` / `#FFB733` (как «Player» на логотипе).
- Фирменный градиент: плавный переход циан <-> оранжевый (используется на прогресс-барах, таймбаре, просмотренной шкале и главной кнопке Play/Pause).
- ПРАВИЛО МИНИМУМА КРАСНОГО И ЗЕЛЁНОГО:
  * Стараться использовать минимум красных и зелёных элементов по всему приложению, выдерживая единую стилистику циан + оранжевый + тёмный графит.
  * Исключение для зелёного: дата/время и строка свежести «Программа обновлена» в настройках EPG может быть зелёным шрифтом (без текста «Всё готово»).
  * Бейдж архива (`↺ 3д` / `АРХИВ`) — строго тонкий и оранжевый (НЕ зелёный/красный).
  * Для избранного вместо сердечек везде используются звёздочки.

3.2. Типографика (`ui/theme/Type.kt`, `res/font/`):
- Шрифты с полной поддержкой кириллицы, гармонирующие с геометричным логотипом:
  * Заголовки: `Montserrat` (`SemiBold`, `Bold`).
  * Основной интерфейс, подписи, тайминги: `Manrope` (`Regular`, `Medium`, `SemiBold`, `Bold`).

3.3. Единая стилистика состояний, загрузок и рамок:
- Все кнопки, карточки, фокус-рамки и индикаторы загрузки во всём приложении должны быть в единой стилистике.
- Избегать разнородных крутящихся Material-спиннеров там, где можно использовать единую фирменную градиентную полосу загрузки / прогресс внутри кнопки или тонкий градиентный индикатор.
- Масштабирование карточек при фокусе не должно обрезаться границами родительских контейнеров (`clipToBounds` / недостаточный `contentPadding` у `LazyRow`/`LazyColumn`/`LazyVerticalGrid`).
- Контраст прогресс-бара под фокусом: на карточке «Продолжить просмотр» при наведении голубой рамки фокуса шкала просмотренного времени снизу НЕ должна сливаться с рамкой фокуса — должна быть чётко различима (градиент, контраст, подложка).

3.4. Иконки:
- Тонкие, лёгкие контурные (outlined/thin-stroke) иконки везде — в левом меню разделов и на панели управления плеера — чтобы они гармонировали с тонкими таймбарами и шрифтом Manrope/Montserrat.

4. НАВИГАЦИЯ С ТВ-ПУЛЬТА (D-PAD), ФОКУС И КНОПКА BACK
================================================================================
4.1. Основные принципы управления:
- 100% функциональности доступно с обычного ТВ-пульта (стрелки Вверх/Вниз/Влево/Вправо, OK/Enter/Center, Back).
- Навигация по меню/спискам никогда не должна требовать мыши или тача.

4.2. Поведение текстовых полей (Настройки URL):
- При наведении фокуса на текстовые поля (URL плейлиста, URL EPG и др.) экранная клавиатура НЕ должна открываться автоматически — только по явному нажатию OK на поле ввода.

4.3. Поведение кнопки Back:
- На Главном экране нажатие `Back` должно открывать диалог подтверждения выхода: «Вы точно хотите закрыть приложение?» (кнопки выхода / отмены с корректным фокусом по умолчанию).
- В подпапках DLNA: нажатие `Back` поднимает на один уровень вверх; на корневом списке DLNA — возвращает фокус в левое меню (или на Главную в зависимости от принятой навигационной модели, без потери фокуса).
- Внутри IPTV-категории: `Back` возвращает к списку категорий/папок плейлиста.
- Внутри плеера:
  * Если открыт попап (аудио/субтитры или телепрограмма) — `Back` закрывает попап С ОДНОГО НАЖАТИЯ (и возвращает фокус на кнопку, его открывшую).
  * Если видны контролы плеера (таймбар + кнопки) — `Back` скрывает контролы С ОДНОГО НАЖАТИЯ.
  * Если контролы скрыты — `Back` закрывает плеер и возвращает пользователя ровно в ту папку DLNA / категорию IPTV / карточку Главной, откуда он был запущен, с фокусом на воспроизводившемся элементе.

4.4. Память курсора в папках DLNA:
- При открытии папки DLNA курсор автоматически переходит НЕ всегда на первый файл, а на тот файл/подпапку внутри этой папки, который открывался в ней последним (если папка открывается впервые — на первый элемент).

6. ГЛАВНЫЙ ЭКРАН (HomeScreen)
================================================================================
- Заголовок «Главная» и описательный подзаголовок сверху УБРАНЫ для экономии полезной площади ТВ-экрана.
- Верхняя часть экрана (1 строка из двух блоков):
  1) Левый блок (~46–50% ширины): «Продолжить просмотр»
     - Показывает до 2 вертикальных постеров фильмов/сериалов (максимум 2, по 1 последнему воспроизводившемуся видео на одну папку — чтобы 10 серий одного сериала не забивали весь блок).
     - Без иконки камеры и подписи «DLNA» на постерe.
     - Название в 1 строку, при фокусе включается бегущая строка (`basicMarquee`).
     - Снизу контрастная градиентная шкала прогресса просмотра, отчётливо видимая даже тогда, когда постер в голубом/градиентном фокусе.
     - Подтягивание вертикальной обложки/постера (из файлов папки DLNA, например `poster/cover/folder`, или онлайн по названию с корректным кэшированием).
     - Если недавно ничего не смотрели — аккуратная заглушка/подсказка.
  2) Правый блок (оставшаяся ширина до правого края): «Избранные папки» (DLNA)

8.2. Карточка канала (компактный вид):

- Фон карточки имеет лёгкий градиентный прогресс-бар текущей передачи (сколько уже прошло от начала передачи).
- Тонкий ОРАНЖЕВЫЙ бейдж архива (например, `↺ 3д`), если у канала настроен catchup/timeshift.
- Кнопка звёздочки «Избранное» с чётким сохранением рамки фокуса при переключении статуса избранного!

8.3. Сортировка внутри категории IPTV:
- Переключение сортировки (по времени просмотра — по умолчанию, далее по алфавиту / по названию / исходный порядок плейлиста).

8.4. Парсинг M3U и XMLTV (`M3uParser.kt`, `XmlTvParser.kt`, `IptvManager.kt`):
- Поддержка M3U/M3U8 (по URL и с локальной флешки/файла), атрибуты `tvg-id`, `tvg-name`, `tvg-logo`, `group-title`, `catchup`, `catchup-days`, `catchup-source`, `timeshift`.
- Поддержка XMLTV (.xml и .xml.gz), корректная работа с часовыми поясами.
- Ограничение глубины архивной истории EPG: загружать/хранить архив EPG только за последние `-3 дня` (только для каналов с архивом / для экономии памяти и времени парсинга, чтобы не вызывать ANR и не переполнять память ТВ).

9. ПОЛНОЭКРАННЫЙ ВИДЕОПЛЕЕР (PlayerScreen, RePlayerEngine)
================================================================================
9.1. Внешний вид и геометрия панели управления:
- Тонкий минималистичный дизайн элементов управления и тонкий градиентный таймбар (без круглой голубой точки-ползунка на конце прогресса в ТВ-режиме).
- Кнопки в тонком контурном стиле, гармонирующие с таймбаром.
- Попадание и перемещение фокуса:
  * Пока панель управления скрыта, первое нажатие OK / Вверх / Вниз (или Меню) может открывать контролы, НО `Влево` / `Вправо` выполняют мгновенную перемотку (см. п. 9.4) без показа контролов!
  * Когда контролы видны: `Влево`/`Вправо` перемещают фокус строго по кнопкам текущей панели (или двигают время на таймбаре, если фокус на таймбаре), не уходя за пределы крайних кнопок и не проваливаясь в фоновую навигацию!
  * По нажатию `Вверх` с панели кнопок фокус переходит на таймбар; по нажатию `Вниз` с таймбара — возвращается на панель кнопок.
- ПРАВИЛО ЗАГОЛОВКОВ В ТВ-РЕЖИМЕ:
  * Под названием канала не показывать лишние технические строки вроде «Источник» / «Звук».
  * При запуске передачи из архива не выводить лишнюю дублирующую плашку с длинным названием под плеером.
  * На таймбаре ТВ показывать время начала и время окончания текущей/архивной передачи.

9.2. Кнопки управления в режиме DLNA (3 кнопки):
1) **Play / Pause** — ОСНОВНАЯ центральная/акцентная кнопка (выделена в наших фирменных цветах: сине-оранжевый градиент).
2) **Следующий файл** — переключение на следующий видеофайл текущей папки DLNA.
3) **Дорожки и субтитры** — ОДНА объединённая кнопка, открывающая единый красивый попап с переключением и аудиодорожек, и субтитров (включая «Отключить субтитры»).

9.3. Кнопки управления в режиме ТВ / IPTV (4 кнопки):
1) **Play / Pause** — главная кнопка с сине-оранжевым градиентным акцентом.
2) **Дорожки и субтитры** — та же объединённая кнопка и единый попап.
3) **Программа передач (EPG)** — открывает аккордеон-попап телепрограммы этого канала:
   - Можно прокручивать вверх к прошедшим/архивным передачам (и вниз к будущим).
   - Плавная анимация раскрытия/выделения элемента, рамка фокуса не обрезается по краям.
   - У раскрытой передачи отображается полное описание.
   - Убрать лишний бейдж «СКОРО» у будущих передач; бейдж «АРХИВ» сделать оранжевым и тонким.
   - Выбор архивной передачи запускает её воспроизведение по catchup URL; если архив недоступен — показать крупное полупрозрачное OSD-уведомление (п. 9.5).
4) **Эфир** (справа) — кнопка возврата в прямой эфир:
   - Имеет визуально активное состояние, когда воспроизводится прямой эфир, и неактивное/доступное для перехода состояние, когда пользователь смотрит архив.
   - При нажатии в режиме архива мгновенно возвращает воспроизведение в прямой эфир.
- ВАЖНО: Кнопка «Назад» (переход к предыдущей передаче) в панели ТВ-плеера УДАЛЕНА — предыдущие передачи выбираются из списка программы передач.

9.4. Логика перемотки (DLNA и ТВ-архив):
- Когда контролы скрыты:
  * Короткое нажатие `Вправо` перематывает вперёд на `+15 секунд`; `Влево` — назад на `-15 секунд`.
  * Если кнопка `Вправо` или `Влево` ЗАЖАТА: начинается ускоренное прибавление/убавление шага (+15 сек, затем ускореннее, но в комфортных управляемых пределах), чтобы удобно проматывать далёкие фрагменты.
  * Перемотка визуализируется только крупным полупрозрачным индикатором/водяным знаком поверх видео (сколько секунд/куда мотаем) БЕЗ вызова панели управления и таймбара!
- Когда фокус стоит НА ТАЙМБАРЕ:
  * Короткое нажатие мотает с базовым шагом, а при ЗАЖАТИИ кнопки через короткое время перемотка тоже должна ускоряться (пользователь зажал — значит, фрагмент далеко).
- Когда идёт ПРЯМОЙ ЭФИР ТВ (и мотать вперёд нельзя):
  * При нажатии `Вправо` при скрытых контролах панель управления не появляется, а на экране появляется еле заметная полупрозрачная надпись `ЭФИР`.

9.5. Информационные и предупреждающие OSD-сообщения поверх видео:
- Предупреждения вроде «Архив недоступен для этого канала» должны отображаться крупным полупрозрачным шрифтом в стилистике обложки RE:Player (аналогично крупной полупрозрачной перемотке), без тяжёлых непрозрачных боксов/плашек и без красных/зелёных тревожных рамок.

9.6. Настройки LibVLC:
- Раздельные буферы кэширования для IPTV (например, `network-caching=3000`, передача `http-user-agent`) и для локального DLNA.
- Надёжный выбор и переключение аудиодорожек и субтитров через API `MediaPlayer` LibVLC.
- Автосохранение позиции просмотра DLNA-видео (при достижении ~90-95% или конце файла помечать/обновлять, при выходе сохранять в `RecentMediaManager`).

10.1. Секция DLNA в Настройках (`SettingsScreen`):

- Справа от поля плейлиста: кнопка «Выбрать с флешки» (системный выбор локального `.m3u`/`.m3u8` файла).
- Справа от поля EPG: информативная статусная кнопка:
  * Показывает статус вида «Программа обновлена» + время последнего обновления зелёным шрифтом (БЕЗ лишних слов «Всё готово»).
  * Автообновление EPG раз в сутки + принудительное обновление по нажатию на эту кнопку.
- Также настройка/иконка диагностики обновления при наличии ошибок загрузки.

10.3. Секция обновлений через GitHub (`UpdateManager`):
- Проверка новых релизов GitHub Releases по тегам/версиям.
- Единая кнопка проверки/скачивания/установки:
  * Прогресс загрузки/проверки отображается прямо ВНУТРИ кнопки в общей стилистике приложения.
  * Оранжевая кнопка «Что нового?» открывает аккуратный диалог с русским списком изменений релиза.
  * После завершения скачивания кнопка превращается в «Установка» (без потери фокуса и без прыжка курсора на Домик!) и запускает системный установщик APK через `FileProvider`.

10.4. Телеметрия сбоев и логов в Telegram (`DiagnosticsSection`, `CrashReporter`, `TelegramConfigServer`):
- Перехват необработанных исключений (UncaughtExceptionHandler) и системных причин завершения процесса Android 11+ (`ApplicationExitInfo`, включая ANR / UI Freeze и нативные крэши).
- Работает для ВСЕХ пользователей «из коробки» за счёт встроенных при сборке через GitHub Secrets параметров (`BuildConfig.DEFAULT_TG_BOT_TOKEN`, `BuildConfig.DEFAULT_TG_CHAT_ID`) — без требования каждому пользователю заводить своего бота.
- Опциональная кнопка «Настройка своего бота (QR)» в настройках для локального HTTP-сервера настройки токена/Chat ID со смартфона (полезно для разработчика/продвинутой отладки) + возможность посмотреть/выгрузить локальные `.txt` отчёты о сбоях и отправить текущий снимок логов вручную.
